# 遥操测试台使用说明

遥操测试台把测试里能自动化的部分做成界面：指标台账、模式切换压测、长测看护、边界探测、VR部分动捕、全身遥操回放、夹爪夹持力、端到端视频延迟。结果都是数字，按 CPI / HPI、摆幅、稳定时间和延迟均值记录。

判定规则来自《Oli 遥操跟随性能与稳定性测试方案》（https://cwjgfm21di.feishu.cn/wiki/ByyqwqbIXiSwTLkG8BNcFx7bnKe ）：

| 规则 | 软件里怎么做 |
|-|-|
| 平地无障碍时绝不能摔倒，一票否决 | 平地场景有摔倒就标“F1 一票否决”，不管目标值是否达到 |
| 跟随到边界后不再跟随可以接受，但边界必须可枚举 | 边界探测里选“饱和”必须写清边界 |
| 目标“待定”的指标首测记基线，版本间不回退 | 同一项按固件版本合计，第一版标“首测基线”，比上一版差就标“比上一版回退” |
| 摆幅：胸腔 2 s 峰峰值（中位 / 最大），目标 4° | 长测看护和边界探测读 IMU 和腰关节自动算 |
| 稳定时间 Ts：松指令后 12 个腿部关节角速度 <0.3 rad/s 并连续 1 s | 长测看护里点“松指令”，自动判定 |
| 模式切换每 20 次统计 | 压测每 20 个循环出一段统计 |
| 每动作 ≥3 次 | 边界探测不足 3 次标黄 |
| 执行节奏：L2 / L4 / L5 每版本，L3 每周，L1 新硬件或新算法时 | 台账页顶部提示哪一层该跑了 |

判定优先级：F1 一票否决 > 不达标 > 比上一版回退 > 达标 > 首测基线。回退的算法：CPI / HPI 越大越好，本版有问题且比上一版小算回退（本版 0 问题不算）；摆幅、Ts、延迟越小越好，比上一版大 10% 以上算回退。

## 安装（Ubuntu 22.04 / 24.04）

1. 解压后进入目录，运行 `bash install.sh`。要联网下载约 300 MB 的 Python 依赖，用时 3–10 分钟。
   - 装了 Miniforge 就建 conda 环境 `teleop-bench`；没装就用系统的 python3 建虚拟环境 `~/.local/share/teleop-bench/venv`。提示“建虚拟环境失败”时，先运行 `sudo apt install python3-venv`（24.04 上是 `python3.12-venv`）。
   - 界面已经在包里构建好，不需要装 Node。
   - 提示“缺系统库：sudo apt install libxcb-cursor0”时照着装。不装的话，X11 会话（登录界面选了“Ubuntu on Xorg”或者用 NVIDIA 显卡）打不开窗口，Wayland 会话不受影响。
   - 24.04 默认限制非特权用户命名空间，内嵌浏览器的沙箱起不来。软件检测到后会自动关闭沙箱，界面只加载本机 127.0.0.1 的页面。
   - 最后一行显示“N passed”就是自检通过。
2. 每台机器人第一次用之前：电脑连上这台机器人的热点（HU_ 开头），运行 `bash robot-access.sh`，按提示输入机器人 limx（1.2）和 guest（1.3）的登录密码。脚本会生成本机密钥 `~/.ssh/oli_robot_manager_ed25519`，记下这台机器人的主机指纹，再把本机公钥授权到机器人上；密码不保存。换另一台机器人时再运行一次。
3. 可选：生成测试记录后“发布到飞书”要用 lark-cli，需要用自己的飞书账号配置好。不发布的话不用装。

## 启动

- 桌面版：应用菜单或桌面上点“遥操测试台”图标，打开独立窗口；关掉窗口软件就退出。命令行启动：在安装目录运行 `./teleop-bench.sh`。
- 网页版（给别的电脑在局域网里看）：在安装目录运行 `bash run.sh`，浏览器打开 http://127.0.0.1:8765 。

两种方式用的是同一份数据，不要同时开。数据存在 `~/.teleop-bench`（台账数据库、SDK 指令审计、录像）。

顶部条显示当前机器人：

| 颜色 | 含义 |
|-|-|
| 墨色 | 已识别真机，显示 SN、固件、状态、电量 |
| 靛紫斜纹 | 演练模式，不连真机，结果不写台账 |
| 橙色斜纹 | 有指令正在发给机器人，这时不能切换模式 |

电脑连上机器人热点后点“重新识别”。只用台账可以不连机器人。

## 切换机器人状态

顶部状态条右边的“切换状态”，任何页面都能用，走机器人 SDK（5000 端口），指令和成功判定和 oli-robot-manager 相同。

| 按钮 | SDK 指令 | 说明 |
|-|-|-|
| 阻尼 | `request_damping` | 全身无力，默认锁住：勾“允许阻尼”再点，并二次确认，只对这一次有效 |
| IKStand | `request_prepare` | 准备站立 |
| Walk | `request_set_walk_mode` | 已经在 Walk 也算成功 |
| 坐下 / 躺下 | `request_from_stand_to_sit` / `request_lie_down` | 吊装保护打开时不能点 |
| 坐姿起身 / 躺姿起身 / 悬吊起身 | `request_standup`（sitting / lying / hanging）→ `request_set_walk_mode` | 两步都成功才算成功；悬吊起身只在吊装保护打开时出现 |

- 吊装保护默认打开（机器人挂着天车），软件记住上次的选择。
- 一次只能执行一个切换；模式切换压测、VR部分动捕、全身遥操回放正在跑时不能手动切。
- 每条指令都记进本地审计日志，失败时显示 SDK 返回的原因和机器人当前状态。

## 指标台账

- 一条记录 = 功能场景 + 问题类型 + 指标 + 总次数（或小时）+ 问题次数。
- 指标：CPI = 总次数 ÷ issue 次数；CPI-F = 总次数 ÷ 摔倒次数；HPI、HPF 用累计小时代替次数。
- 0 次问题写成“总数+”，例如 `136+（136/0）`。样本不超过 3 次标“样本少，只作参考”。
- 填了目标值，达标显示青绿，不达标显示红色。目标值和产品对齐后再填；空着时第一版自动当基线。
- 新增记录时选测试层级（L1–L5），并勾选是否平地无障碍。CPI-F、HPF 在平地场景有摔倒，标“F1 一票否决”。
- 同一（场景，问题类型，指标）按固件版本合计，右侧显示本版合计和上一版。
- 顶部“执行节奏”：连着真机按机器人的固件版本判断，否则按台账里最新的版本；该跑的层标橙色。视频延迟测量算 L2。
- 下方“测量值”是摆幅、Ts 这类越小越好的量，长测看护结束时自动写入。
- “复制为飞书文本”按 `场景（问题类型），CPI = x（总/问题）` 一行一条复制，F1、不达标、回退会跟在后面，直接贴进报告。

## 模式切换压测

1. 选序列：坐下 ↔ 起身、躺下 ↔ 起身、Walk ↔ 动作库、Stand ↔ Lie ↔ Move（躺下 → 起身到 Stand → 进 Move，新序列，第一次在真机上跑先跑 1 个循环看看）。
2. 填循环次数（默认 20，每 20 次出一段统计）和每步后的等待时间。
3. 吊装保护打开时，坐下、躺下类序列不能选。
4. 真机要勾选“已确认现场”才能开始。
5. 每一步等机器人返回成功才走下一步；默认失败一次就停。“停止”只停后续调度，不打断正在执行的动作，紧急情况用遥控器或急停。
6. 现场看到摔倒点“记一次摔倒并停止”：立即停止后续调度，按平地摔倒记 F1。不用 IMU 自动判摔，因为躺下时骨盆本来就会倾斜到 90° 左右。
7. 结束后每种切换按 CPI 写进台账（层级 L4），备注里有耗时中位和最长；整个序列再写一条 CPI-F（总数 = 完成的循环数）。
8. “每 20 次一段”表看耗时是否随次数变长；一段里有失败或摔倒就判不通过。

## 长测看护

1. 填场景（同名场景在台账里归到一起），选是否 SSH 读姿态和关节（/ImuData 约 50 Hz、/joint/state 约 48 Hz，在主控上降采样后再传），勾选是否平地无障碍。
2. 开始计时。换电池、调整场地时点“暂停计时”。
3. 自动检测：
   - 机器人状态变成阻尼、异常类状态，记一条“异常停机”；
   - |roll| 或 |pitch| 超过阈值（默认 60°，同主控 FallDetector）并持续 0.2 s，记一条“疑似摔倒”。
4. 自动检测到的事件都是“待确认”，要人逐条判为摔倒、issue 或忽略；现场看到的问题点“记一次 issue / 摔倒”。
5. 胸腔摆幅：胸腔姿态 = 骨盆 IMU + 腰部三个关节换算，每 2 s 一个窗口算 roll、pitch 峰峰值，显示中位和最大，目标 ≤4°。窗口里一半以上时刻腿部关节在动（角速度 ≥0.3 rad/s）算“运动中”，只按运动中的窗口判定；暂停和疑似摔倒的那段不计。
6. 稳定时间 Ts：操作员松开指令的同时点“松指令”，软件等 12 个腿部关节角速度都 <0.3 rad/s 并连续 1 s，Ts = 点下到静止开始的时间。10 s 内没稳定记一条“Ts 超时”待确认。
7. 结束时写入两条台账：HPF（摔倒）和 HPI（含摔倒的全部 issue），层级 L3；摆幅 roll、pitch 和 Ts 写进“测量值”。平地场景有摔倒标 F1。
8. 读不到数据时界面会写原因，例如“/ImuData：No found topic”，一般是机器人运控还没启动。

## 边界探测（L4）

《Oli遥操-脚本v4》全部演示动作加控制权交接、启停边界，VR 全身动捕下逐项探边界，天车保护。

1. 选控制器 WBT 或 LBMotion。同一天同一台机器两种都测，页面下方自动出双控制器对比表。
2. 想要每次的胸腔摆幅峰值，勾选“读姿态”，每次动作前点“开始这次”。
3. 按“边界执行”做完一组（例如高抬手 ×10）记一次结果：
   - 完成：完整跟随；
   - 饱和：到边界后不再跟随，可以接受，但必须在输入框写清边界（例如“抬膝到胸前一半，频率 >1.5 Hz 不跟”）；
   - 未跟随：范围内没跟上，算 issue；
   - 摔倒：F1，一票否决。
4. 每个动作至少 3 次，不足标黄。完成度 = （完成 + 饱和）÷ 次数，目标 100% 且不摔。
5. 点“写入台账”：每个（控制器，动作）写 CPI-F 和 CPI（未跟随含摔倒）各一条，层级 L4，边界和摆幅峰值写在备注。再点一次是更新，不会重复写。

## VR部分动捕

测 VR部分动捕下摇杆指令（`/vr_cmd`）的跟随：指令、LBMotion 内部、机器人实际各是多少，以及松手后还滑多远。整个过程只按两个按钮：“开始录包”和“结束并出报告”。

1. 打开“VR部分动捕”页，左边是机器人检查清单。没连机器人时，下面会列出附近 `HU_` 开头的热点，点“连接”即可；第一次连的热点要输入密码。连上后软件自动做 4 项检查：
   - 连接机器人：SSH 登录主控 1.2，读 SN、版本、电量；
   - 分析脚本：按 MD5 核对主控 `~/Cyres/lbm/tools/lbmtools/` 里的 4 个脚本（含灵巧手分析 hand.py），没有或不一致就自动上传；
   - 录包工具：主控上有 `mrosrecord`，并且没有别的录包在跑；
   - 磁盘空间：剩余 ≥ 5 GB。
   全部打勾才能开始。换一台机器人会自动重新检查。
2. 右边选测试项（前进、后退、左移、右移、左转、右转）和次数（默认 5），点“开始录包”。
3. 弹窗会列出要做的步骤并实时提示。主控后台在录包，同时读 `/cmd_vel` 数推杆次数：
   - 前 10 秒左右显示“正在连接指令流，先别推杆”，变绿显示“可以推杆”后再动手；
   - 推着时显示计时，满 5 秒响一声；松手后提示等机器人站稳 3 秒；
   - 推了别的方向会提示，不计数。
4. 做够次数后弹窗变绿，点“结束并出报告”。软件依次停止录包、校验 MD5、在主控上分析、生成报告，大约 20–40 秒。弹窗里直接显示指令 → 内部 → 实际、实际/指令、偏移率、松手到停下的时间和多走的距离。
5. 报告存在 `~/.teleop-bench/lbm/<日期>_<SN>/报告.md`，本场所有记录合在一份里，每次结束自动更新。报告开头是“怎么看”：指令、LBMotion 内部、实际各是什么，相邻两级对比看出什么，配一张逐次的柱状图（`img/链路.png`）；逐次表每行项名前带推杆开始的时刻，精确到秒。录包里没有 LBMotion 内部速度的推杆（机器人当时不在 LBMotion 下走）单独标出，不计入汇总。点“复制报告”可以贴到飞书。
6. 录完发现某次推杆中途松手、被人扶，在“逐次”表里写原因点“排除”，报告会重新生成。中途不想要这次录包，点“放弃这次”，主控上的录包也会删掉。
7. 录包默认留在主控 `~/Cyres/lbm/bag/`。需要留存时点“拷回本机”，会拷到本场文件夹的 `bag/` 下并核对 MD5。以前录的包可以在“分析本机已有录包”里填路径。

摇杆对应：左手摇杆前后是前进后退，左手摇杆左右是横移，右手摇杆左右是转向（按 /vr_cmd 和 /cmd_vel 录包核对）。一次录包最长 15 分钟，超时自动结束并出报告。

### 一键测（软件代替手柄）

不用人拿 Pico。软件替手柄发 `/vr_cmd`，每个版本输入完全一样，结果和手动推杆写进同一份记录和报告。有两类：

| 类 | 内容 | 看什么 |
|-|-|-|
| 推杆脚本 | 固定的摇杆指令：前进后退、左右横移、左右转向 | 指令 → LBMotion 内部 → 实际，松杆后停多快 |
| 工作包 | 真人在 VR部分动捕下干活时录的手柄数据：“灵巧手取放杯”（低台前蹲下取放杯子，再转身走约 1.4 m 到航空箱前取放，198 s） | 推杆跟随，加灵巧手 指令 → 实际 |

1. 左边检查清单打勾；关掉 Pico；机器人在 Walk 站稳、挂天车、遥控器在手上。
2. 选脚本：前进后退、左右横移、左右转向（每组都是来回，走完基本回到原地），选来回几次（默认 3），点“开始”。选工作包时没有次数，播一遍；场地空着就行，不用摆物体，四周留 2 m，天车绳长够骨盆往下 0.3 m（中途会下蹲）。
3. 软件依次：确认 `/vr_cmd` 没有别的发布者 → 把遥操预选模式设成 0（VR部分动捕）→ 录包 → 播脚本（RG+A 进模式、按住两个握把、按动作表推满摇杆、最后 RG+B 回 Walk）→ 停录包 → 主控分析 → 出报告 → 把预选模式恢复成原值。
4. 弹窗里实时显示正在做哪个动作；有危险先按遥控器急停，再点“停止”。中途停止时机器人可能还在遥操里，用遥控器切回 Walk。结束后弹窗问这次要不要保存：保存就计入报告，不保存就不进报告，录包和原始记录都留着。全身遥操回放中途停止也一样。

工作包结果：里面的推杆列在“逐次”表，标“工作包里的推杆”，不计入汇总（推的时长、方向和脚本不一样）。灵巧手单独一节：遥操发给手的开合（`/brainco2/hand/cmd`）和手指实际位置（`/brainco2/hand/state`）比，开合度取食指到小指 4 根的平均；指令越过最大开合的一半算一次开合，实际 2 s 内也越过一半算跟上，记响应时间和没跟上的时刻。

摇杆方向按 660 录包核对：左摇杆 `leftJS[1]` 正为前进，右摇杆 `rightJS[0]` 负为左转；横移 `leftJS[0]` 负为左移，按同样约定推定。

每次推杆算什么：

| 环节 | 数据 | 说明 |
|-|-|-|
| 指令 | `/cmd_vel` | 稳态区间均值 |
| LBMotion 内部 | `/lbmotion_states` data[1] 前后速度、data[2] 转向角速度 | 横移没有对应字段，记“—” |
| 实际 | 腿部正运动学 + IMU 姿态估骨盆位移；骨盆 IMU 偏航 | 转向单位 °/s，平移 m/s |
| 推杆过程 | 主方向行程、侧向偏移（左正）、偏移率、朝向变化 | 按推杆开始时的朝向分解 |
| 松手后 | 停下时间、多走的距离或多转的角度、朝向变化、抬脚次数 | 平移看骨盆水平速度连续 0.5 s < 0.05 m/s；转向看偏航角速度连续 0.5 s < 5°/s |

稳态区间是推杆开始 2 s 后到松手，推杆不足 4 s 时取后一半，稳态短于 1 s 的次数不计入速度比。录包开始时已经在推杆的那一段不计。算法用旧录包核对过：648 旋转实际 / 指令 63.6–64.1%（旧报告 62.4–64.8%），11-03 268 前进松杆停下 1.53 s、多走 0.30 m，和 `coast.py` 一致。

## 全身遥操回放（WBT）

不用人遥操。软件把录好的全身动捕包（在 660 上用 Pico + 5 个 tracker 录：11-19 的 6 个基线动作，11-20 的灵巧手工作包）播给机器人，机器人当成真人在遥操。每个版本都播这几个包。软件同时录下重定向输出和机器人实际，算出 人 → 重定向 → 机器人 每一级差了多少，按严重度列成差距清单给研发。每次输入完全一样，所以不同版本、不同机器人可以直接比。

1. 打开“全身遥操回放”页，左边是机器人检查清单，连热点的方法和 LBMotion 页相同。软件自动检查 6 项：连接机器人；回放工具和动作包（按 MD5 上传到主控 `~/Cyres/wbt/`）；`mrosrecord`、`mrosplay` 可用；磁盘剩余 ≥ 3 GB；遥操节点在跑（`/teleop/state` 有数据）；Pico 已断开（`/vr_cmd` 没有发布者，否则真人和回放两路指令混发，机器人会抖）。
2. 右边选动作包：前进、后退、左行、右行、SKU、转身，以及灵巧手工作包“灵巧手捡瓶”（反复深蹲、侧身弯腰够地上的瓶子，再站着用右手在航空箱上取放，170 s）和它的前 40 s“灵巧手捡瓶_前40s”。下面按步骤准备：挂天车、留空地、遥控器拿在手上、关掉 Pico、机器人在 Walk 站稳。
   - 灵巧手工作包：场地空着就行，不用摆物体；机器人周围 1.5 m 内不站人；会深蹲到手贴地，天车绳长要够骨盆往下 0.4 m。第一次在一台机器人上播，先播“前40s”，稳住了再播完整包。
3. 点“开始”。软件先确认遥操预选模式是 VR全身动捕（不是就切过去，测完恢复）。弹窗显示进度：录包 → 3 秒后回放 → 播完再录 2 秒 → 拷回电脑 → 分析。回放开头机器人会自己进入全身遥操（RG+A，再按住握把），结尾自己回 Walk（RG+B）。有危险先按遥控器急停，再点“停止”。
4. 结果在页面下方，一次一张卡片：人 / 重定向 / 机器人 的前进、侧移、转角；差距最大的 6 项；骨盆最大俯仰、横滚；有灵巧手数据时加左右手开合跟上次数和响应时间；一张对比图（骨盆轨迹俯视、偏航曲线、差距最大的部位、跟踪误差最大的关节，有灵巧手时再加左右手 指令 / 实际 开合曲线）。
5. 报告存在 `~/.teleop-bench/wbt/<日期>_<SN>/报告.md`，图在 `img/`，录包在 `bag/`，点“打开报告文件夹”。报告结构：怎么看（每个数据是什么、相邻两级对比看出什么）→ 总表 → 31 个关节误差热力图 → 灵巧手 指令 → 实际（有灵巧手数据时）→ 差距清单（重定向→机器人：全身控制器没做到；人→重定向：重定向没算对）→ 逐次的部位表和全部关节表 → 方法。每行项名前带开始播包的时刻，精确到秒。差距清单每条带时刻（跟随开始后第几秒），研发可以对着录包和视频找。
6. 页面上的“版本对比”表汇总所有真机测试里播同一批基线包的结果，每个动作、版本、机器人取最新一次；报告里也有这一节。完成率 = 机器人 ÷ 重定向（主方向：前进后退看前进位移，横移看侧移，SKU 看偏航净转角，转身看右转最深的角度）。回放包 MD5 对不上、中途停止、演练和离线分析的结果都不算进去。
7. 以前录的全身动捕包可以在“分析已有录包”里填路径，不连机器人也能出结果。

| 级 | 数据 | 算什么 |
|-|-|-|
| 人 | `/tf` 中 `pico_origin` → `/vr_body/*` 24 个关节 | 骨盆位移和偏航；头、双手、双脚相对骨盆的位置 |
| 重定向 | `/teleop/wb_cmd`（frame_id world）的 anchors 和 joint_cmd | 同上，对应 base_link、head_pitch_link、wrist_roll_link、ankle_roll_link |
| 机器人 | `/ImuData` 偏航、`/joint/state`、腿部里程计 | 偏航、位移、骨盆最大俯仰和横滚、31 个关节的跟踪误差均方根和滞后 |
| 灵巧手 | `/brainco2/hand/cmd` → `/brainco2/hand/state` | 每次开合多久跟上、没跟上的时刻、开合度误差 |

回放包在 `assets/wbt/`：6 个基线动作来自 11-19 660 录的全身动捕包；“灵巧手捡瓶”来自 11-20 660 录的全身动捕包，“前40s”是它跟随开始后的前 40 s。转身包只截原包跟随后 17.5–44 s 的原地转圈（先右转约 2 圈，再左转约 2 圈）。做包时只留跟随段的 `/vr_cmd` 和人体 `/tf`，清掉动作里的 A/B/X/Y（全身模式下单按 A/X/Y 会切控制器）。开头补 2.5 s 进入遥操，结尾补 1 s 回 Walk，播放前把时间戳改成当前时间。

加新动作：录一个 Pico 全身动捕原始包，在 `backend/` 下运行 `python -m bench.wbt.pack make <原始包> ../assets/wbt/<动作>.bag`，只要其中一段时加 `--clip 起 止`（秒，相对跟随开始）。再把动作加进 `bench/wbt/runner.py` 的 `ITEMS`。

加半身工作包：录一个 VR部分动捕原始包，运行 `python -m bench.wbt.pack make <原始包> ../assets/lbm/<名字>.bag --half`（只留 `/vr_cmd`），再加进 `bench/lbm/runner.py` 的 `WORKPACKS`。录原始包要带上 `/vr_cmd`、`/teleop/state`、`/brainco2/hand/cmd`、`/brainco2/hand/state`。

## 夹爪夹持力

软件依次把 LimX 二指夹爪的夹持力设成 默认、0、100，每一档操作员用特殊塑料杯夹一次、拍照，点“已完成”才切下一档。

1. 机器人装 LimX 二指夹爪、挂天车；Pico 进入 VR部分动捕并跟随，扳机能控制夹爪。
2. 选左、右或两侧，点“开始”。软件先读默认值（一般 80），当前档位就是默认值。
3. 弹窗里：把杯子放到夹爪中间，扳机按到底夹 3 秒，拍照上传（至少一张），可以写形变情况，点“已完成”。没传照片按钮点不了。
4. 软件设下一档并回读，回读和设定不一致会标红。每档点“已完成”时顺带读一帧 `/limx/2F-gripper/cmd` 的 tau。
5. 三档做完自动恢复默认值并回读；中途点“放弃这一轮”也会恢复。报告和照片在 `~/.teleop-bench/gripper/<日期>_<SN>/`。

设置只对本次运行有效，重启遥操服务后恢复 80。

## 端到端视频延迟

方法：屏幕闪烁块加两台 USB 双目相机。A 拍屏幕，B 拍 Pico 镜片，B 里每次翻转减 A 里对应那次就是延迟，以均值和 P5–P95 为准。

页面最上面是今天要测的矩阵：近场 H264 / H265 / JPEG，远程阿里云 / 腾讯云 H264。只算最新固件版本的数据。每格计划 2 次，横条是均值，细线是 P5–P95，橙色竖线是目标（近场 ≤100 ms，远程 ≤150 ms）。有上一版数据时显示上一版均值，比上一版高 10% 以上标红“比上一版回退”，生成的测试记录里也会写进结论和问题表。点一行，下面的链路和编码会切到这一格。

步骤：

1. 打开闪烁页：在外接屏全屏打开，机器人头部相机对准它。Alt+F4 退出。
2. 选相机并各截一张，确认两路都拍到闪烁块。两台相机不要插在同一个 USB 2.0 HUB 上，否则第二台打不开。插拔相机后点“刷新相机列表”。
3. 校准：两台都对着屏幕录 30 s。换了相机或 USB 口要重新校准，一般在 ±5 ms 以内。
4. 测量：B 放到 Pico 镜片前，Pico 进入遥操、画面稳定后开始。
   - “机器人视频配置”一栏自动读出机器人现在的近场编码、远程用阿里云还是腾讯云及其编码。读的是 1.3（视频服务 pico_teleop_server 所在的板子）上的 `/opt/limx/install/etc/livekit/configs/oli_edu_mros.yaml`：近场看 `local.codec`；远程看 `remote.trro.enabled`（腾讯云 TRRO）和 `remote.livekit.enabled`（阿里云 LiveKit）哪个是 true，以及它的 `codec`。腾讯云的编码以 `/opt/limx/install/etc/livekit/configs/trro/config.json` 里每路视频的 `codec` 为准（0 = H264，1 = H265），yaml 里 `remote.trro.codec` 对腾讯云不起作用；切腾讯云编码时软件会同时改这两个文件（改前都备份，“还原”时一起还原）。新刷的包会把 config.json 重置。1.2 上也有同名文件，但视频服务不读它。
   - 和要测的不一致时有两个办法：点“按机器人现在的配置测”，把下面的链路、编码改成机器人实际的；或者点“切到 X 并重启视频服务”。切换要 1.3 的 sudo 密码（guest 账号），在界面里输一次，只存在本次运行的内存里，关掉软件就没了。
   - 切换时软件会：核对 SN → 当天第一次改之前把原文件备份到 1.3 的 `~/Cyres/backup_video_<日期>/` → 只改需要的几行（远程切换会同时改两个 enabled 和目标链路的 codec）→ 写入并核对 md5 → 重启 `pico_teleop_server` 并确认它的启动时间变了、状态 running → 读回核对。任何一步不对都报错停下。Pico 要重新连接。
   - 测完点“还原原配置”，用当天最早的备份还原。
   - 点“开始测量”时软件会再读一次机器人配置，和选的链路、编码不一致就不让测；读到的配置记进这次结果的备注。读不到配置（例如没连机器人热点）时可以勾选“跳过核对”，这次结果会标“配置未核实”。
   - 名称会自动加上时分秒（如 `jpeg1_153012`），同名不会覆盖之前的录像。
5. 结果自动进“历次结果”和上面的矩阵。配对数应接近翻转数（至少一半），否则这次无效，点垃圾桶删掉，不进对比和报告。
6. 生成测试记录：填依据文档和补充说明，点“生成测试记录”。软件按《专项测试记录模板》生成飞书文档（要点、测试准备、结果表、对比图、每次的分布图和 A|B 画面、10 s A|B 并排视频、脚本原件、结论和问题表），并做写作规范检查。错误为 0、通读无误后点“发到飞书”，建在“我的文档库”里。发布要先装好 lark-cli 并登录。

注意：配置里写着“头显不支持该编码时自动退回 JPEG”，切 H264、H265 后要在 Pico 上确认画面正常，并记下实际用的编码。

### 常见问题

| 现象 | 原因 | 处理 |
|-|-|-|
| 分析没有得出统计结果，提示相机 B 没录到 | 相机录像中途 USB 掉线（系统日志 error -71），或设备号变了 | 重新插相机，最好换口或换线；点“刷新相机列表”，重新选相机、重新校准后再测 |
| 第二台相机打不开，提示 No space left on device | 两台相机插在同一个 USB 2.0 HUB 上 | 分开插到电脑不同的 USB 口 |
| 配对数不到翻转数的一半 | B 没对准镜片里的闪烁块，或画面卡顿、黑屏 | 调整 B，确认 Pico 画面流畅，删掉这次重测 |
| 校准值超出 ±5 ms | 相机帧率不稳或拍屏幕时曝光过度 | 确认两台都是 2560×720 30 fps，调暗屏幕后重新校准 |
| 顶部显示没有识别到机器人 | 电脑网卡自动切回了别的网络 | 重新连机器人热点，再点“重新识别” |
| 读取视频配置报 SSH 失败 | 这台机器人的 1.3 还没授权本机密钥，或 1.3 的主机密钥没记录 | 终端执行一次 `ssh-copy-id -i ~/.ssh/oli_robot_manager_ed25519.pub guest@10.192.1.3`（输 guest 密码），再 `ssh -i ~/.ssh/oli_robot_manager_ed25519 guest@10.192.1.3` 确认能免密登录 |
| 切换报“sudo 密码不对” | 输的不是 1.3 guest 账号的密码 | 重新输入 |
| 切换报“没有重启成功” | 视频服务重启后没起来，或启动时间没变 | 点“读取”看服务状态；再切一次，还不行找开发 |
| 发到飞书失败 | lark-cli 没登录或已过期 | 终端执行 `lark-cli auth status` 检查 |

## 安装（给新电脑）

1. 装 Miniforge（mamba）到 `~/miniforge3`。
2. `git clone https://github.com/cyres03/teleop-bench.git`（或解压源码包），在目录里执行 `bash install.sh`。
3. 最后显示“25 passed”和“装好了”即可，桌面和应用菜单里会出现“遥操测试台”。

## 安全约定

- 改机器人配置、重启服务、下发运动指令前，界面都会要求确认。
- SSH 只接受本机 `~/.ssh/known_hosts*` 里记录过的主机密钥，连上后核对 SN，和顶部识别的不一致就停止。
- 1.3 的 sudo 密码只在本次运行的内存里，通过标准输入交给 sudo，不出现在命令行、日志和磁盘上。
- 密码不进软件，SSH 用密钥登录。
